# 帳票読取デモ（新規アップロード ＋ ファイル一覧 ＋ マイタスク）

> 帳票タイプ／帳票分類（業務区分）／確認详情の UI は同目录 `llm ocr NL` 原型に合わせて復元しています。

既存製品「帳票読取」の Level 0（必須）要件の動くデモです。頂栏で **新規アップロード** と **ファイル一覧** と **マイタスク** を切り替えられます。
モックデータのみで動作し、外部通信・ビルドは不要です。

## 起動

```
open demo/index.html
```

## 0. ナビゲーション（メニュー／タブ）

* **上部の帯＝メニュー**（左から）：**ホーム／新規アップロード／ファイル一覧／マイタスク／帳票設定▾／利用設定▾**。「帳票設定」「利用設定」はサブメニュー。「マイタスク」は未対応／対応済（确认・承认はここから详情壳で実施）。
  サブメニューの開閉は **CSS の hover ＋ クリックのトグル**で、**外側クリックで閉じます**（開閉のたびに再描画すると hover が外れず“貼り付いた”ままになるため、hover では再描画しません）。
* **その下の帯＝タブ**：開いている画面のタブ。`✕` で閉じられ、最後の1枚は閉じられません（閉じると操作不能になるため）。タブをクリックするとその画面に切り替わります。
* **新規アップロード**と**ファイル一覧**は頂栏の独立メニューです（旧「帳票読取」傘は廃止）。
* **ファイル一覧**は左にファイルツリー＋右にステータスタブ／一覧の2ペイン。左右カラムは同じ高さに固定し、はみ出しは各カラム内でスクロールします。
* **新規アップロード**は全幅（サイドバーなし）。アップロード後「選択帳票読取」でファイル一覧へ遷移します。
* ツリーのノードアイコンは **業務＝分類アイコン／帳票タイプ・ファイル＝ファイルアイコン**。
* ファイル一覧の列構成（帳票タイプ・サイズ・ステータス・処理履歴・作成日時・更新日時・操作）はそのまま維持しています。
* ホームは左メニューを持たず全幅（ご利用履歴のみ）。
* **設定画面（帳票設定／利用設定）の左メニュー**は「帳票設定／権限／利用設定」の 3 グループ 8 項目（`renderCfgNav()`）＝ 帳票タイプ・帳票分類・辞書登録 ／ 帳票権限管理 ／ ユーザー管理・権限設定・セキュリティ設定・ログ設定。**利用設定の各画面（ユーザー管理・権限設定・セキュリティ設定・ログ設定・外部API）は左メニューを出さず全幅**で表示します（`CFG_NO_SIDEBAR = ['users','roles','security','logs','api']`、`.layout-pane.layout-noside` で 1 カラム化）。帳票設定側の左メニューは従来どおりです。

## 0-a. マイタスクとファイル一覧の役割分担

* **ファイル一覧**：読取後の全ファイル進捗一覧（详情・进度の閲覧：プレビュー／再読取／削除）。確認・承認・任意ダウンロードは置かない。
* **マイタスク**：要確認／要承認 Tab。担当グループ（帳票権限管理のフロー担当）でフィルタし、详情壳で確認または承認／差戻。
* **CSV 出力**：承認済み（または承認不要で確認済み）のみ。形式は帳票タイプ設定・ステップ2のフィールドマッピング。
* **権限**：承认人は **帳票設定 → 帳票権限管理** で割り当て（利用設定の権限設定とは分表）。

| 優先度 | 分類 | 機能 | 本デモでの実装 |
| --- | --- | --- | --- |

| Level 0 | 権限管理 | 帳票権限管理（帳票タイプ単位・ロールグループ／ユーザー） | ✅ `#page=permissions`（**帳票タイプ×4業務操作（閲覧/確認/承認/再承認）**のマトリクス＋ロールグループ一覧） |
| Level 0 | システム部署 | システム部署 | 画面ではないため対象外（構築作業）。デモはマルチテナント構成で表現 |
| Level 1 | システムアーキテクチャ | マルチテナント改修（データ分離・GPU共有） | ✅ ヘッダーの**テナント切替**でデータ分離を再現（3テナント・重複なし） |
| Level 1 | 自動化処理 | ファイルアップロード自動化 | ✅ `#page=api`（アップロードAPI／**SHA-256ハッシュで二重取込防止（409）**／Webhook） |
| Level 1 | データ出力 | CSV出力形式設定 | ✅ **エクスポート設定**ダイアログ（**横向固定**、列名・列順・文字コード・改行・区切り・空値・日付形式）。同一帳票タイプの複数ファイルは**1ファイルに自動結合（1ファイル1行）**。テーブル列は設定した上限まで **`テーブル名_列名_1..n`** に横展開。列設定は管理者のみ |
| Level 1 | 結果承認 | 読取結果の承認フロー（9状態） | ✅ 9状態のタブ＋**確認→承認1→承認2→出力**。**差戻は直前の段へ**、**承認記録は保持**、コメント任意。カテゴリ単位で**承認不要**にも設定可（確認済み→出力済み） |
| Level 1 | UI設計 | 全ページのデザイン刷新（電算の配色・レイアウト） | ✅ 電算システム公式サイトの配色で全画面を再設計 |

**2026年内のキーとなる設計判断（要件表の客户回答より）**

* 承認は **ファイル単位・可変段数**（帳票タイプの権限表で「再承認」に担当を入れれば 2 段、空なら 1 段）。差戻は**ひとつ前の段**へ戻し、**過去の承認記録は保持**。
* 承認コメント・差戻理由は**同じ入力項目**（任意）。初期段階では同一人物の兼務を禁止しない。
* **帳票権限は「帳票タイプ×4 業務操作」単位**（閲覧 → 確認 → 承認 → 再承認）。**承認＝1 段目、再承認＝2 段目の承認**で、1 段承認で運用する帳票タイプは「再承認」を空欄にします。担当は**ユーザーグループ／ユーザー／ロール**を混在で指定でき、**1 グループは複数ロール**・**1 ユーザーは複数グループ**（多対多）。**システムレベルのメニュー権限（利用設定 ＞ 権限設定）とは別テーブル**で管理します。
* CSV は**フィールドマッピング方式**（プロンプトでフォーマットを決めない）。読み取り精度と出力形式を分離。
* 自動取込は**外部API＋Webhook**で実現（共有フォルダ監視ではない）。**重複はファイルハッシュで判定**。

## 0-1b. 帳票権限管理（業務レベルの権限）

**2 つの権限層を同じ表に混ぜない**のがこの画面の前提です。

> **⚠️ この節は現行デモの実装（旧版）です。** クライアント回答を反映した設計案では、
> **ワークフロー担当**（確認グループ／承認グループの 2 種類の専任グループ。帳票タイプごとに「グループ全体＝ランダム割当」か「グループ内の特定の人」を選び、2 段承認はスイッチ）と
> **権限**（閲覧／アップロード／出力。別表）を**分ける**方針に変わりました。
> 現行デモの「帳票タイプ × 4 業務操作」マトリクス（閲覧／確認／承認／再承認を 1 表に混在）はこの方針に合わせて作り直す予定です。
> 正は `../権限設計_担当グループ方式.md`（中国語版は `../权限设计_担当组方式.md`）。

| 層 | 管理画面 | モック | 何を決めるか |
| --- | --- | --- | --- |
| システムレベル | 利用設定 ＞ 権限設定（`#page=roles`） | `ROLES` ＋ `MENU_TREE` / `MENU_PERMS` | どの画面に到達できるか（メニュー権限） |
| 業務レベル | 権限・連携 ＞ 帳票権限管理（`#page=permissions`） | `TICKET_PERMS` | 帳票タイプごとに、どの操作を誰ができるか |

* **単位は帳票タイプ × 4 業務操作**（閲覧 → 確認 → 承認 → 再承認）。承認＝1 段目、**再承認＝2 段目の承認**。1 段承認で運用する帳票タイプは「再承認」を空欄にします。
* **この権限表が承認フローの唯一の正**：承認段数（1 段／2 段）は「再承認に担当が入っているか」から導出します。`APPROVAL_CONFIG`（帳票タイプ単位）は**承認を使うかどうかだけ**を持ち、担当は持ちません。画面で担当を変えると、マイタスクの絞り込み・担当列、確認画面の「担当：」表示、処理履歴の検索にそのまま反映されます。
* 担当の照合は**所属グループ**と、権限表で**ユーザーを直接指定**した場合の両方を見ます（`state.currentGroups` / `state.currentUser`）。
* **2 段承認では次の担当が段で切り替わります**（1 段目＝承認、2 段目＝再承認）。`approversFor()` が `flowOf().done` を見て決めます。
* 担当は **ロールグループ／ユーザー／ロール**を混在で指定できます。**1 グループは複数ロール**を持て、**1 ユーザーは複数グループ**に所属できます（多対多）。グループは**部門ではなくロール（役割）のまとまり**として定義します（部門の概念は廃止）。
* セルをクリックすると **帳票権限の設定** ダイアログ（ロールグループ／ロール／ユーザーの 3 列・複数選択）が開きます。「クリア」でその帳票タイプの 4 操作をまとめて空にします。
* 権限設定（`#page=roles`）の **新規権限作成／編集** は「権限名・権限ID・概要・ステータス（トグル）」の 4 項目（`roleFormDialog()`）。**メニュー権限** は画面到達権限のツリー（親＝配下リーフを一括選択、部分選択は半選択表示）を開きます（`menuPermDialog()`）。
* 閲覧・アップロード・結果修正・確認・承認・CSV 出力・帳票設定変更などの機能は、この表をもとに権限チェックする想定です。
* **未決（旧）**：権限の単位を上位の類型（8 件）に引き上げるかは検討中。現状は帳票タイプ（24 件）単位で実装しています（上位で既定を決め、帳票タイプで上書きする二段構えが候補）。
  → **解決済み：製品の階層は 業務区分 ＞ 帳票タイプ ＞ ファイル**（中間層の語は製品にありません）。呼称は**帳票タイプに統一**し、権限の単位も**帳票タイプ 1 本**で扱います（デモ固有の中間層も帳票タイプと呼びます）。

| 2 | **読取待ち** | `● 読取待ち` ／ 帳票タイプ欄に**プルダウン**（初期値＝自動判別結果） | タイプを確認・変更 → 行をチェック → **選択帳票読取** |
| 3 | **読取中** | 押下直後に**ファイル一覧へ自動遷移**（タブ＝読取中）。一覧でも経過秒数を表示 | 約4秒で完了／失敗へ更新 |
| 4 | **読取完了** / **読取失敗** | `● 読取完了` ／ `● 読取失敗` ＋ **エラー理由**。読取が終わると**結果に対応するタブへ自動で移る**（成功→読取完了／全滅→読取失敗／混在→すべて）ので、その帳票が必ず見えます | 失敗行は新規アップロード画面で再選択→「選択帳票読取」で再実行可 |

* **手動分類**：分類完了後、帳票タイプのプルダウンまたは操作列の `手動分類` で選び直せます（選択中の業務区分に紐づくタイプのみ）。
* **操作・処理**列は `プレビュー` / `手動分類` / `🗑` の3つ。
* 「選択帳票読取」は読取処理中でも一覧へ遷移します（完了を待たない）。
* **遷移時に表示条件をリセット**：新規行が絞り込み条件・ツリー検索語・ツリー選択で隠れないよう、`選択帳票読取` 押下時に絞り込み条件とツリー検索語を既定へ戻し、ツリー選択を「すべて」にします。
* **タブの件数バッジは表と同じ母集団**：絞り込み条件・ツリー検索語を反映して数えるため、「バッジは 1 なのに表は空」という食い違いは起きません。ツリー検索は入力のたびに一覧とバッジへ即反映されます。

## 1-2. 読取結果確認ページ（`#page=review`）と操作アイコン

一覧の「操作・処理」列は **详情／再読取／ダウンロード／削除 の4アイコンのみ**（ホバーでツールチップ表示・`data-tip` を `position:fixed` で描画するため表のスクロール領域でも切れません）。確認・承認はここからは開かず、**マイタスク → 読取結果確認ページ**で操作します。

| アイコン | ツールチップ | 動作 |
| --- | --- | --- |
| `i-view` | 详情 | **ページプレビュー（帳票のページ画像モーダル）を開く**。確認画面へは遷移しません |
| `i-scan` | 再読取 | 読取をやり直す（読取中→完了/失敗、経過秒数を表示） |
| `i-download` | （ツールチップなし） | **アイコンに hover すると形式メニューが開く**：Excel／CSV／JSON の3形式。`position:fixed` で body 直下に出すため表のスクロール領域でも切れません。クリックでもトグル可（タッチ・キーボード用）。表をスクロールすると自動で閉じます |
| `i-delete` | 削除 | 行を削除 |

* **ページプレビューは画像だけ**：ヘッダー／メタ情報／操作ボタンのバーは置きません（`.pv-back` / `.pv-stage`）。閉じるは右上の `×` か背景クリック。複数ページの帳票のときだけ、左右のオーバーレイ矢印（`‹` `›`）でページ送りできます（1ページなら矢印も出ません）。アップロード画面の「プレビュー」と一覧の「详情」は同じモーダルです。
* プレビューの様式名・様式番号は**その行の帳票タイプに追従**します（`mockSheet(pn, total, layoutId)`）。ページ数はファイルサイズから決定的に導いたモック値です。
* ファイル名リンクをクリックした場合は従来どおり**読取結果確認ページ**（閲覧のみ）を開きます。

### 承認の進捗はどこで見るか

| 場所 | 見えるもの |
| --- | --- |
| **読取結果確認ページの上部** | `確認 → 承認1 → 承認2 → 出力` のステップ表示。完了＝青丸チェック、現在＝青枠の丸、未処理＝グレー。右端に `1 / 2 段階承認済み` のような要約バッジ（差戻中は警告色で「差戻中」） |
| **処理履歴ダイアログ（確認ページの `処理履歴`／`承認`）** | 同じステップ＋各段の**実行者・日時・コメント**、下部に処理履歴テーブル（差戻後も記録は保持） |
| **一覧の「操作・処理履歴」列** | 直近の処理内容（`確認担当者: 〜`／`承認1済み（残り1段階）`／`差戻中（確認者へ戻し）` など） |

* 承認不要に設定した帳票タイプは **`確認 → 出力`** の2ステップだけを表示し、要約は「確認済み（承認不要）」になります。
* ステップは**帳票タイプの段数設定（1段階／2段階／承認不要）に自動追従**します。

**読取結果確認ページ**（実機の確認画面に合わせた構成）

* 左：帳票プレビュー（前へ／次へ・幅に合わせる・回転・拡大縮小・**項目位置マーカー**の表示切替、ページ番号 1/2/3）
* 右：`Preview` / `JSON` タブ、読取テキスト（**項目ラベル＋読取値**。修正すると緑に変わり「修正済み」に計上）、テーブル情報読取、`エラー箇所のみ表示`・`一括確認` スイッチ
* 上部：確認待ち／確認済み／項目合計／修正済みの件数、操作ガイド、履歴、ダウンロード
* 下部のボタンは**帳票の状態で切り替わります**（製品と同じ並び）：

| 状態 | 下部ボタン |
| --- | --- |
| 読取完了／読取失敗／差戻中（未確認） | `履歴`・`閉じる`・`保存`・**`確認`（オレンジ）** |
| 確認済み（承認待ち）※承認あり | `履歴`・`閉じる`・`保存`・`差戻`・**`承認`（青）** |
| 確認済み ※承認不要カテゴリ | `履歴`・`閉じる`・`保存`・**`出力`（青）** |
| 承認済み | `履歴`・`閉じる`・`保存`・`差戻`・`承認`（次の段） |
| 出力済み | `履歴`・`閉じる`・`保存`（編集のみ） |

* **`保存` は修正内容の保存だけ**を行い、ステータスは進めません。ステータスを進めるのは **`確認`** です。
* `確認` で読取結果を確定 → **確認済み（承認待ち）**になり、確認日時と確認担当者を記録。以降 `承認`（2段階／1段階）→ `出力` と進み、`差戻` は直前の段へ戻します（記録は保持）。
* 未実装だった `エラー箇所のみ表示`・`一括確認` のスイッチも、行の状態に応じて動作します。

## 3. 実装した要件

1. **ツリー自動生成**（要件1）
   業務 ＞ 帳票タイプ ＞ ファイル の3階層（左カラム・ファイル一覧に配置）。業務・帳票タイプから自動生成し、各ノードに配下件数を表示します（帳票タイプの直下が PDF ファイル。**版式はツリーの階層にはせず**、ファイルの属性として保持し、絞り込みと「帳票タイプ（版式）」列・チップで表現）。
   階層は固定せず、業務なし・版式なしの組織も許容する前提です。左右のパネルは高さを揃えています。
2. **手動リネーム**（要件2）
   ツリーの ✎（**既定は非表示で、ノードにホバーすると表示**）で**ファイル名**を、帳票タイプ（版式）の表示名を各画面から変更できます。**業務名・帳票タイプ名はマスタ設定側で管理するため変更できません**（✎ はファイルと版式にのみ表示）。
   変更は**表示名のみ**で、実ファイル名・帳票タイプID・格納パス・エクスポート名・操作ログは不変です。ツリー・一覧・絞り込みの検索は変更後の表示名で動作します。
3. **検索と絞り込み・ソート**（要件3）
   絞り込みエリアは **1行目にステータス／帳票タイプ／処理ユーザ／確認者**、右端に **アイコンのみの `検索`・`リセット`（各28×28・横並び）と `もっと見る`** を置きます（日本語ラベルは出さず、`title` / `aria-label` で補います）。**既定は閉じた状態**で、`もっと見る ∨` で追加条件を展開します。
   **帳票タイプの絞り込みは1階層**（帳票タイプ名のみ。カテゴリ名を前置した「カテゴリ / タイプ」の連結表記は使いません）。帳票タイプの絞り込みも1階層（カテゴリ名のみ）です。実環境の帳票タイプ値も「T_農林水産_要件6_品種登録簿」のように単独名です。
   条件は **ステータス／業務区分／帳票タイプ**（既定表示）＋「もっと見る」で **作成者／確認者／承認者**、加えて日付レンジ（作成日時・更新日時・読取日・確認日・承認日）。**絞り込みはすべて単一選択**です。
   絞り込みは**枠の入れ子をやめた1階層のレイアウト**で、行ごとに「ラベル＋コントロール」を揃えて表示します（日付レンジは3行目に集約）。
   **条件間は AND（同時滿足）**。有効条件はチップで可視化し、個別解除が可能。「閉じる ∧」で絞り込みエリアを畳めます。表ヘッダクリックでソート（初期値：更新日時の降順）。
4. **既存画面の踏襲**
   ステータス色分け、ステータス連動の操作アイコン、ページャ、一括操作ボタン、操作・処理履歴、**帳票タイプ（版式）列**。画面上に説明文・説明用ボタンは置かない方針（仕様は README に集約）。

## 9. 帳票タイプの確認

**自動分類 → 確認**の流れです。

1. **自動分類**：アップロード直後はステータス `要確認`（件数バッジ付き）。ファイル名などから帳票タイプを自動判別し、`読取待ち` になった時点で**帳票タイプ欄に判別結果がプルダウンで入ります**。
2. **確認**：内容が正しければそのまま「選択帳票読取」へ。違う場合は**プルダウンから保存済みの帳票タイプを選び直せます**。
3. **ページプレビュー**（モーダル／确认画面）：アップロード画面と一覧の「详情」は**画像だけを見せるモーダル**（操作ボタンのバーなし・複数ページは左右の矢印）。确认画面のプレビューは製品（llm ocr NL）と同じレイアウトです。

## 11. 配色・デザインの方針

電算システム公式サイト（<https://www.densan-s.co.jp/>）の CSS から実際の値を抽出し、その配色とトーンに合わせています。

| 用途 | 値 | 出典 |
| --- | --- | --- |
| コーポレートカラー（アクティブタブ下線・選択中のツリー・チップ・強調文字） | `#2448A0` | サイト内で最も使われている青（ナビ下線・見出し左線・ボタン） |
| プライマリボタン | `linear-gradient(45deg,#2A5DD8,#2A99D8)`／hover で `#2AA9D8→#2AD8D8` | 公式サイトの `.button01.first` と同じ |
| 補助アクセント | `#2A99D8` | リンク・フォーカス |
| 注意・処理中 | `#FF6600` | サイトの第2アクセント（`#FF6600→#FF9900`） |
| 本文 | `#333333` / 補助 `#676767` / 淡 `#999999` | サイト本文色 |
| 背景・罫線 | `#F7F7F7` / `#E7E7E7` / `#D7D7D7` | サイトの背景・罫線 |

デザイン方針：影（box-shadow）を使わない、角丸は 2px、罫線は 1px の薄グレー、色は「選択・操作」にだけ使う。グラデーションは公式サイトのプライマリボタンにのみ適用し、他の要素はフラットに統一。行の操作アイコンは既定で枠なし（hover で枠と色）にして情報量を抑えています。

## 12. 実装メモ（不具合と対策）

* **押しても変化が見えないボタンの扱い**：「検索」は同一データを再計算するだけでは反応が分からないため、実行時に `検索しました：N 件が該当しました` のトーストと、条件行の件数表示（`条件に一致：N 件` / `全 N 件`）でフィードバックします。「リセット」は条件が未指定のときは無効化し、実行時もトーストを出します。ホームの既定期間（2026-09-14〜2026-10-14）は「条件未指定」として扱います。
* **バインドは画面ごとに分割**：`bind()` を `bindTree` / `bindTreeExtra` / `bindResultPanel` / `bindHomePanel` / `bindPaneNav` / `bindUploadPanel` / `bindDdCommon` に分割し、存在しない要素（例：ホーム画面の `#tree`）で例外が出ても他のバインドが止まらないようにしています。以前は `#tree` が無い画面で `bind()` が例外を投げ、タブの `✕` やメニューが無反応になっていました。
* **ルートとページ番号の分離**：`state.page`（home/upload/result）と `state.resultPage`（一覧のページ番号）を分けています。同じ変数を使い回すとハッシュ経由でルートが壊れ、画面が空になります。
* **アップロードの帳票タイプ推定**：ファイル名からキーワードで推定し、判定できない名前は先頭の帳票タイプに寄せます（`null.id` 参照で例外にならないようにするため）。
